# Security Policy

## Supported version

The `main` branch is the supported production line.

## Reporting a vulnerability

Please do not publish sensitive vulnerability details in a public GitHub issue.

Use a private security reporting channel available through GitHub for this repository, or contact the repository owner privately before disclosing exploit details.

When reporting, include:

- affected component/path
- impact
- reproduction steps
- suggested mitigation, if known

Never include API keys, passwords, tokens, personal access tokens, or other secrets in a report.

## Credential exposure

If a secret is found in the repository, assume it is compromised, rotate it immediately, then remove it from the active codebase and clean history when appropriate.
